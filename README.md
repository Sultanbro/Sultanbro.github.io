# Telegram WebApp — выбор товаров и оплата

Небольшой проект на **Python и aiogram**: Telegram-бот открывает веб-каталог, получает выбранную позицию и выставляет счёт через Telegram Payments. Интерфейс написан на HTML, CSS и JavaScript с использованием Telegram WebApp API.

## Сценарий работы

1. Пользователь отправляет боту `/start`.
2. Бот показывает кнопку `Site`, которая открывает WebApp.
3. Пользователь выбирает одну из шести позиций каталога и подтверждает выбор основной кнопкой Telegram.
4. JavaScript передаёт идентификатор позиции через `Telegram.WebApp.sendData()`.
5. Python-обработчик получает `web_app_data`, выбирает цену из словаря `PRICE` и отправляет счёт.
6. Бот обрабатывает запрос перед оплатой и сообщает о получении события успешного платежа.

```text
/start → кнопка Site → WebApp: HTML / CSS / JavaScript
                              ↓ sendData(item_id)
Python / aiogram ← web_app_data
       ↓ send_invoice
Telegram Payments → successful_payment → сообщение пользователю
```

## Что реализовано

- Команда `/start` и клавиатура с кнопкой запуска WebApp.
- Сетка из шести позиций с выбором одного товара.
- Использование основной кнопки Telegram и цветов его темы.
- Получение данных из WebApp асинхронным обработчиком бота.
- Формирование счёта с ценой из Python-кода; в запросе указана валюта RUB и сбор email и телефона.
- Обработчики `pre_checkout_query` и `successful_payment`.
- Загрузка токенов из переменных окружения.

Каталог и цены заданы в коде. Корзина, база данных, учёт заказов и административная панель в проекте не реализованы.

## Технологии и структура

| Файл | Назначение |
| --- | --- |
| [main.py](main.py) | Создание бота и диспетчера, запуск long polling |
| [handlers.py](handlers.py) | Команда старта, получение выбора, счета и события оплаты |

Код использует интерфейсы **aiogram 2.x**: `Dispatcher`, `executor.start_polling` и декораторы `message_handler`. Пример такого API есть в [официальной документации aiogram 2.25.1](https://docs.aiogram.dev/en/v2.25.1/quick_start.html). Для перехода на другую основную версию библиотеки потребуется адаптировать код.

## Подготовка запуска

Нужны Python, отдельное виртуальное окружение, Telegram-бот, тестовые настройки платёжного провайдера и HTTPS-хостинг для статических файлов.

Пример установки зависимости для используемого API:

```sh
git clone https://github.com/Sultanbro/Sultanbro.github.io.git
cd Sultanbro.github.io
python3 -m venv .venv
. .venv/bin/activate
python -m pip install 'aiogram==2.25.1'
```

Файл зависимостей и проверенная матрица версий Python пока отсутствуют. Установка и сквозной запуск в новом окружении не проверены.

### Веб-интерфейс

Разместите `index.html`, `app.js`, `style.css` и `1.png` на HTTPS-хостинге. В [keyboards.py](keyboards.py) замените URL в `WebAppInfo` на адрес размещённой страницы. Сейчас в коде указан `https://sultanbro.github.io/`; доступность размещённой версии не проверялась.

Бот запускается отдельным Python-процессом. Статический хостинг обслуживает только веб-интерфейс.

Для сценария отправки данных открывайте страницу кнопкой `Site` из личного чата с ботом. Такой способ передачи описан в [документации Telegram](https://core.telegram.org/bots/webapps#keyboard-button-mini-apps). При обычном открытии страницы в браузере контекст пользователя Telegram может отсутствовать; текущий `app.js` обращается к нему напрямую.

### Переменные окружения

| Имя | Значение |
| --- | --- |
| `BOT_TOKEN` | Токен вашего Telegram-бота |
| `PAYMENTS_TOKEN` | Тестовый токен платёжного провайдера, подключённого к боту |

Передайте обе переменные процессу через настройки IDE или менеджера процессов, затем запустите:

```sh
python main.py
```

`config.py` читает переменные окружения через `os.environ`. Файл `.env` автоматически не загружается; `.env.example` служит перечнем имён. При отсутствии любого из двух значений приложение останавливается с ошибкой конфигурации. Токены должны оставаться в окружении Python-процесса и не попадать в статические файлы.

## Проверка сценария

После настройки тестового окружения проверьте `/start`, открытие WebApp, выбор позиции, получение счёта и сообщение об успешной тестовой оплате.

Сейчас `pre_checkout_query` подтверждается без дополнительной проверки заказа, а идентификатор позиции используется как ключ словаря `PRICE`. Следующие шаги развития — валидация входных данных, сохранение заказов, проверка суммы и статуса перед подтверждением, обработка ошибок и повторных событий. Реальные платежи в рамках проверки проекта не выполнялись.
